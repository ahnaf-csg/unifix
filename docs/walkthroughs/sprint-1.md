# Sprint 1 Walkthrough

Sprint goal: **users can log in by role** (`01_project_plan.md`). Features: C-01 accounts and roles, C-15 profile, C-16 setup. Rules: VR-11, VR-13, VR-15.

Updated after the Sprint 1 review round: login type tabs (CR-10), three-zone top bar (CR-11) and fixes I-31 to I-35. Sections marked *(review)* changed in that round.

Each section lists what a file does and the key lines both team members should be able to explain. Read the files in this order; later files build on earlier ones.

## 1. Project setup

### `requirements.txt`
Pinned versions, so everyone installs the same thing: Django 5.2.18 (LTS), python-dotenv (reads `.env`), and Django's own dependencies (`asgiref`, `sqlparse`, `tzdata`; `tzdata` gives Windows the time-zone data that `Asia/Dhaka` needs).

### `.env.example`
Template for the private `.env` file (never committed). Holds `SECRET_KEY`, `DEBUG`, `ALLOWED_HOSTS`.

### `.gitignore` *(review)*
Lists what Git must never commit: `.venv/`, `db.sqlite3`, `media/`, `.env`, and since I-32 also `.claude/` (local Claude Code settings such as `launch.json`, and its worktrees folder).

### `manage.py`, `unifix/__init__.py`, `unifix/wsgi.py`, `unifix/asgi.py`
Generated by `django-admin startproject`, unchanged. `manage.py` runs commands; `wsgi.py` and `asgi.py` are entry points a web server would use in deployment. All three point Django at `unifix.settings`.

### `unifix/settings.py`
- `load_dotenv(BASE_DIR / ".env")` copies values from `.env` into the environment; `SECRET_KEY = os.environ.get("SECRET_KEY")` then reads them. The project refuses to start without a key (`ImproperlyConfigured`).
- `DEBUG = os.environ.get("DEBUG", "False") == "True"`: environment values are strings, so compare with `"True"`.
- `INSTALLED_APPS` lists the four UniFix apps from `05` §2.
- `"DIRS": [BASE_DIR / "templates"]`: project-level templates folder (`base.html`, partials).
- `AUTH_USER_MODEL = "accounts.User"`: use our User model instead of Django's. **Must be set before the first `migrate`**; changing it later is very hard.
- `AUTHENTICATION_BACKENDS = [...AllowAllUsersModelBackend]`: Django's default backend silently refuses inactive users, so the login form could only show a generic error. This backend lets the form see the user and say "Account inactive" (VR-11). The form still refuses the login.
- `LOGIN_URL = "accounts:login"`: where `@..._required` sends anonymous users.
- `TIME_ZONE = "Asia/Dhaka"`, `USE_TZ = True`: times are stored in UTC and shown in Dhaka time.
- `STATICFILES_DIRS`, `MEDIA_ROOT`: where CSS/JS live and where uploads will go (Sprint 2).
- *(review)* `if len(sys.argv) > 1 and sys.argv[1] == "test": PASSWORD_HASHERS = [MD5PasswordHasher]`: Django's real hasher is deliberately slow (to resist password guessing), which made the tests take about 50 s. Only when running `manage.py test`, we switch to the fast MD5 hasher; the suite now runs in under a second. Real logins never use MD5 (I-33).

### `unifix/urls.py`
The root URL table. Each app's URLs are included under a prefix (paths from `05` §4):
- `path("", RedirectView.as_view(pattern_name="accounts:login"))`: `/` goes to login, and the login page forwards signed-in users to their home. So `/` always lands in the right place: login, S-01 or A-01 (checked by TC-27). The UniFix wordmark and the error pages link to `/` for that reason.
- `path("student/", include("complaints.urls"))`: student pages live in the `complaints` app but use the `student` namespace.
- `path("django-admin/", admin.site.urls)`: Django admin is *not* at `/admin/`, to avoid confusion with our admin console.

### `accounts/apps.py`, `complaints/apps.py`, `notifications/apps.py`, `console/apps.py`, and each `__init__.py`
Register each folder as a Django app. `notifications` is empty until Sprint 3 and `console` has no models (it shows data from other apps), so neither has a `migrations/` folder yet.

## 2. Models and migrations

### `complaints/models.py`
- `Department`: `name` and `code` are `unique=True` (`05` §3).
- `Category.department = models.ForeignKey(Department, on_delete=models.PROTECT, related_name="categories")`
  - `PROTECT`: a department that still has categories cannot be deleted (deactivate it with `is_active` instead).
  - `related_name="categories"` lets us write `department.categories.all()`.
- `requires_attachment` is stored now and enforced in Sprint 2 (VR-08).

### `accounts/models.py`
The most important file this sprint.
- `class User(AbstractUser)`: we keep Django's password hashing, `last_login`, `date_joined`, `is_active` and so on, and change the rest.
- `username = None`, `first_name = None`, `last_name = None`: removes those inherited fields; `full_name` replaces the names.
- `USERNAME_FIELD = "email"`: email is the login identifier. `REQUIRED_FIELDS = ["full_name"]` is what `createsuperuser` asks for.
- `UserManager.create_user()`: Django's default manager expects a username, so we need our own that creates users by email and hashes the password with `set_password()`. `create_superuser()` always makes a Super Admin.
- `class Role(models.TextChoices)` and `class AccountState(...)`: stored values (`dept_admin`) and display labels (Department admin), as in `05` §1.
- `student_id = models.CharField(..., null=True, blank=True, unique=True)`: databases allow many NULLs in a unique column but only one `""`. So empty student IDs are stored as NULL: `self.student_id = self.student_id or None` in `save()`.
- `department = models.ForeignKey("complaints.Department", ...)`: a string reference, because `complaints` also needs `accounts`. This is why the accounts migration depends on the complaints migration.
- `clean()`: role rules checked by forms and the Django admin (students need an NSU email; Dept Admins need a department; only Dept Admins have one; only students have a student ID).
- `save()`: **derived fields** that can never get out of step:
  - `self.is_active = self.account_state == self.AccountState.ACTIVE`: Django itself refuses inactive users, so suspending an account blocks it (VR-11).
  - `self.is_staff = self.is_superuser = self.is_super_admin()`: only the Super Admin can open `/django-admin/` (C-16).
  - The email is lower-cased so `Rafiq@...` and `rafiq@...` are the same account.
- `suspend()`, `reactivate()`, `soft_delete()`: only change `account_state`; `save()` updates `is_active`. Soft delete keeps the row so complaint history survives (`07`).
- Not yet built: `can_view_complaint()` from `05` §3 needs the `Complaint` model (Sprint 2).

### `complaints/migrations/0001_initial.py`, `accounts/migrations/0001_initial.py`
Generated by `makemigrations`. They create the tables. The accounts migration lists `("complaints", "0001_initial")` in `dependencies` because `User.department` points at `Department`. Never edit an applied migration; make a new one.

## 3. Django admin (C-16)

### `complaints/admin.py`
- `@admin.register(Department)` puts the model on `/django-admin/`.
- `inlines = [CategoryInline]`: a department's categories can be edited on the department page.
- `list_display`, `list_filter`, `search_fields`: columns, sidebar filters and search box of the list page.

### `accounts/admin.py`
Django's `UserAdmin` assumes a `username`, so we adjust it:
- `UserAdminCreationForm(BaseUserCreationForm)` with `fields = ["email", "full_name", "role", "department", "student_id"]`: the "Add user" form, with two password boxes.
- `fieldsets` and `add_fieldsets`: the field layout for edit and add.
- `readonly_fields = ["is_active", "is_staff", "is_superuser", ...]`: shown but not editable, because `User.save()` sets them from `account_state` and `role`. To suspend someone in the admin, change **Account state**.

## 4. Forms, permissions and views

### `accounts/forms.py`
- `LoginForm(AuthenticationForm)`: Django's login form. Its field is still called `username`, but it holds the email because `USERNAME_FIELD = "email"`.
  - *(review)* `login_type = forms.ChoiceField(choices=[("student", "Student"), ("staff", "Staff")], initial="student", widget=forms.RadioSelect)`: the Student/Staff tabs (CR-10). `RadioSelect` renders radio buttons, which the template styles as tabs. `field_order` puts it first.
  - *(review)* `__init__` sets `self.fields["username"].widget.input_type = "email"`, so the field renders as `type="email"` (phones show the email keyboard; TC-35). Each form gets its own copy of its fields, so this does not affect other forms.
  - `clean_username()` lower-cases the email so the lookup matches.
  - `confirm_login_allowed()`: Django calls it only after the email and password are correct. Raising `ValidationError` stops the login. The order of the checks matters:
    1. inactive account: "Account inactive" (VR-11), so a suspended user never learns anything more;
    2. *(review)* tab vs role: `user.is_student()` needs `login_type == "student"`, everyone else needs `"staff"`, otherwise "This is a ... account. Please use the ... tab." (VR-15).
  - The messages live in `error_messages`, so tests and templates use one copy of the text.
- `RegisterForm(BaseUserCreationForm)`: adds password + confirm-password checks and Django's password rules.
  - `clean_email()`: VR-13, the email must end with `@northsouth.edu` and must not exist already (`email__iexact`, case-insensitive). `endswith` also rejects tricks like `@northsouth.edu.fake.com`.
  - `save()` sets `user.role = User.Role.STUDENT`. The form has no `role` field, so a posted `role` value is ignored (TC-14).
- `ProfileForm`: only `full_name` and `phone` (C-15). Any other posted field is ignored (TC-20).

### `accounts/permissions.py`
The one place where role checks live (CLAUDE.md).
- `role_required(*roles)` builds a decorator. For each request it:
  1. sends anonymous users to login (`redirect_to_login` keeps `?next=`),
  2. signs out users whose account was suspended after they logged in (`if not user.is_active: logout(request)`, VR-11),
  3. raises `PermissionDenied` (HTTP 403) if the role is not allowed.
- `student_required`, `admin_required`, `super_admin_required`, `signed_in_required` are ready-made versions. A view is protected by writing `@student_required` above it; hiding a link in a template is never enough.

### `accounts/views.py`
- `role_home_url(user)`: students go to `student:home` (S-01), both admin roles to `console:dashboard` (A-01) (P-01).
- `UniFixLoginView(LoginView)`: Django's login view with our form and template. `redirect_authenticated_user = True` skips the page for signed-in users. `get_default_redirect_url()` returns `role_home_url(...)` when there is no `?next=`.
- `register()`: the usual pattern: `GET` shows an empty form; `POST` validates, saves, signs the student in with `login(request, user)`, adds a success message and redirects (Post/Redirect/Get, so refreshing does not resubmit).
- `profile()`: saves name and phone; also passes an empty `PasswordChangeForm` so both forms are on one page (S-06).
  - *(review)* `ProfileForm(request.POST, instance=User.objects.get(pk=request.user.pk))`: a ModelForm copies valid posted values onto its instance even if another field fails. If that instance were `request.user`, the top bar would show the unsaved name (I-31). Editing a fresh copy from the database keeps `request.user` unchanged (TC-26).
- `password_change()`: only accepts `POST` from the profile page. `update_session_auth_hash()` keeps the user signed in after the password changes (otherwise Django signs them out). If the form is invalid, it re-renders the profile page with the errors.

### `accounts/urls.py`, `complaints/urls.py`, `console/urls.py`
- `app_name = "accounts"` / `"student"` / `"console"` sets the namespace, so templates write `{% url 'accounts:login' %}`. Names are exactly those in `05` §4.
- `path("logout/", LogoutView.as_view(), ...)`: Django 5 only logs out on `POST` (a link can't log you out by accident), so the top bar uses a small form.

### `complaints/views.py`
`@student_required def home(request)`: S-01 placeholder. Stat cards and the "Needs your action" list arrive with complaints in Sprint 2.

### `console/views.py`
`@admin_required def dashboard(request)`: A-01 placeholder. It already shows the scoping rule used everywhere in the console: the Super Admin sees `Department.objects.all()`, a Dept Admin only `filter(pk=request.user.department_id)` (VR-02). `prefetch_related("categories")` loads all categories in one extra query instead of one per department.

## 5. Templates and static files

### `templates/base.html`
The page skeleton every page extends.
- `<meta name="viewport" ...>`: makes phones use their real width (NFR-05).
- `{% include "partials/topbar.html" %}` always; the sidebar only `{% if user.is_authenticated %}`.
- `{% block title %}` and `{% block content %}` are what child templates fill in.

### `templates/partials/topbar.html` *(review: rewritten for CR-11, then amended)*
Three zones (`04` Layout):
- `topbar-left`: an empty `<div>`. It keeps the grid balanced so the centre group stays centred, and is reserved for a future mobile menu button.
- `topbar-center`: one link `<a class="brand" href="/">` holding the NSU logo and the wordmark side by side:
  - `<img class="topbar-logo" src="{% static 'img/nsu_logo.png' %}" alt="North South University" width="36" height="36">`. `{% load static %}` is needed in this file because `{% load %}` is not inherited from `base.html`. `width`/`height` reserve the space before the image loads.
  - `<span>UniFix<small>...</small></span>`: the name and the subtitle ("NSU Campus Services" or "Admin Console").
- `topbar-right`, only `{% if user.is_authenticated %}`: search, bell, user menu. Login and register therefore show the bar without tools.
- Search is `disabled` until C-18 (Sprint 4); the bell has no count until notifications exist (Sprint 3).
- The avatar has `title="{{ user.full_name }}"` because the name is hidden on narrower screens.
- `{{ user.get_role_display }}`: Django adds `get_<field>_display()` for every choices field, which returns the label ("Department admin").
- Logout is a `<form method="post">` with `{% csrf_token %}` (NFR-02).

### `templates/partials/sidebar.html`
Role-specific links (`04` Layout).
- `{% with page=request.resolver_match.view_name %}` gives the current URL name, used to add `sidebar-link-active`.
- `{% if user.is_student %}` calls the model method; templates call methods without brackets.
- Pages from later sprints are `<span ... aria-disabled="true">` (visible, not clickable).

### `templates/partials/messages.html`
Shows Django messages (`messages.success(...)` in views) with `alert-{{ message.level_tag }}`: `alert-success`, `alert-error`, and so on.

### `templates/accounts/login.html` *(review: tabs for CR-10)*
- `<fieldset class="tab-list" aria-label="Log in as">` groups the tabs; screen readers announce the group name with each choice.
- `{% for radio in form.login_type %}<label class="tab" ...>{{ radio.tag }} {{ radio.choice_label }}</label>`: each tab is a `<label>` wrapping a real radio button, so clicking anywhere on the tab selects it.
- Keyboard support comes free from the browser: Tab moves into the radio group (to the checked one), arrow keys move and select. No JavaScript.
- `<div class="tab-panel" data-tab="student">` / `data-tab="staff"`: the hint above the fields and the line under the button (register link, or the "created by the Super Admin" note). CSS shows only the panels for the checked tab.
- Because the radio is a form field, the chosen tab is posted with the email and password, and stays selected when the page shows an error.

### `templates/accounts/register.html`, `profile.html` (and the shared form pattern)
- `{% csrf_token %}` in every form (NFR-02).
- `{% for field in form %}` loops through the form fields and prints the label, the input (`{{ field }}`) and its errors, wrapped in `form-field`.
- `form.non_field_errors` holds errors that belong to the whole form, such as "Account inactive".
- `profile.html` has two forms posting to two URLs: `accounts:profile` and `accounts:password_change`.

### `templates/403.html`, `templates/404.html` *(review, I-34)*
Django looks for these exact names. Both `{% extends "base.html" %}`, so signed-in users keep their top bar and sidebar, and both link "Back to your home" to `/`.
- 403 is raised by `accounts/permissions.py` (`PermissionDenied`) and shows in any mode.
- 404 only uses `404.html` when `DEBUG=False`; with `DEBUG=True` Django shows its developer page instead. To look at it: set `DEBUG=False` in `.env`, run `python manage.py runserver --insecure` (otherwise CSS is not served), then set `DEBUG=True` again. Tests always run with `DEBUG=False`, so TC-29 checks it.

### `templates/student/home.html`, `templates/console/dashboard.html`
Placeholder home pages. The dashboard loops `department.categories.all()` to show where complaints will be routed.

### `static/css/unifix.css`
The single stylesheet, ported from `docs/mockups/unifix.css`.
- Section 1 holds the design tokens from `05` §6 (`--navy`, `--primary`, …); everything else uses `var(--token)`.
- Layout: `body:has(> .sidebar) { display: grid; grid-template-columns: 232px 1fr; }`. Pages with a sidebar become a two-column grid, and the top bar spans both columns (`grid-column: 1 / -1`). Login and register have no sidebar and show a centred card instead.
- *(review)* Top bar (§4): `.topbar { display: grid; grid-template-columns: minmax(0, 1fr) auto minmax(0, 1fr); align-items: center; }`. The two outer columns are always equal, so the middle one (logo + wordmark) is exactly centred, with or without the right zone. Inside it, `.brand { display: flex; align-items: center; }` puts the 36 px logo and the text block on the same centre line.
- *(review)* `.topbar-right > :not(.topbar-search) { flex-shrink: 0; white-space: nowrap; }`: when space runs out only the search box shrinks; the bell and user menu never wrap.
- *(review)* The search box's magnifier is a small SVG written into the CSS (`url("data:image/svg+xml,...")`), so there is no extra image file.
- *(review)* Tabs (§10b): the radio button is made invisible (`opacity: 0`, 1 px) but **not** `display: none`, which would make it unreachable by keyboard. `.tab:has(input:checked)` styles the active tab (blue text, tinted background, blue underline); `.tab:has(input:focus-visible)` draws the keyboard focus outline. `form:has(input[value="staff"]:checked) .tab-panel[data-tab="staff"] { display: block; }` swaps the panels.
- Class names are exactly those in `05` §5 (badges, `pri-*`, `btn-*`, `form-*`, `alert-*`, `topbar-*`, `tab-*`, ...).
- Breakpoints (§13): below 1300 px the user's name hides (the avatar stays); below 1000 px the tools move to a second row under the centre group; below 800 px the sidebar becomes a sideways-scrolling row, the NSU logo shrinks to 30 px and search collapses to its icon; only below 360 px does the wordmark text shrink too.

### `static/img/nsu_logo.png` *(review, CR-11)*
The university's logo, added unchanged (600 x 600 PNG). The browser scales it down to 36 px high; `05` §2 records its name.

### `static/js/unifix.js`
Empty helper file (only a comment) so the structure matches `05` §2. Sprint 2 adds small helpers (file previews).

## 6. Seed data and tests

### `complaints/management/commands/seed_demo.py` (and the two `__init__.py` files)
A custom `manage.py` command: Django finds any `management/commands/<name>.py` with a `Command` class.
- `DEPARTMENTS`, `DEPT_ADMINS`, `STUDENTS`: plain lists matching `05` §7.
- `update_or_create(code=..., defaults={...})`: finds the row by the first argument and updates it, or creates it. This is why running the command twice creates no duplicates (TC-24).
- `user.set_password(DEMO_PASSWORD)`: passwords are always hashed, never stored as text.
- `@transaction.atomic`: either everything is seeded or nothing is.

### `accounts/tests.py`, `complaints/tests.py`
35 tests, `TC-01` to `TC-35` (see `10_test_plan.md`).
- *(review)* `login_data(user_or_email, login_type=None)` builds the login POST and picks the matching tab unless a test asks for a wrong one; the VR-15 tests (`LoginTypeTests`) pass it on purpose.
- *(review)* `ErrorPageTests` uses `assertTemplateUsed(response, "403.html")` to prove the friendly page (not Django's default) was rendered.
- Each test runs in a fresh, empty test database.
- `self.client.post(reverse("accounts:login"), {...})` submits a form like a browser would.
- `self.client.force_login(user)` signs in without a password (for tests that are not about login).
- `assertRedirects`, `assertContains`, and `"_auth_user_id" in self.client.session` (is someone signed in?) are the main checks.
